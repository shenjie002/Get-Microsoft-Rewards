# Get Microsoft Rewards（修复/增强版）

[![License: MIT](https://img.shields.io/badge/License-MIT-yellow.svg)](LICENSE)
[![Platform](https://img.shields.io/badge/Platform-Tampermonkey%20%7C%20ScriptCat-green.svg)](https://www.tampermonkey.net/)

Microsoft Rewards 浏览器用户脚本：提供积分状态面板、签到、阅读、活动和搜索任务，并支持在打开 Rewards 仪表板后自动启动任务。

本项目基于 Muverix 的修复/增强版继续修改。本次新增了仪表板自动执行功能和 Chrome / Tampermonkey 安装、权限配置说明。自动执行修改已通过 JavaScript 语法检查，实际任务是否成功取决于登录状态、账号资格、地区和微软接口。

> 这是用户脚本，需要 Tampermonkey 等脚本管理器，不是独立 Chrome 扩展，也不需要部署服务器。自动化可能违反 Microsoft Rewards 使用规则，存在账号风控、封禁或积分清零风险，请自行评估。

## 新版页面兼容状态（v1.0.21）

新版 Rewards 使用 Next.js Flight。脚本安全解析 JSON 文本分片，使用服务端 `profilePictureUrl` 中严格限定为 `https://storage.live.com/users/0x…/myprofile/expressionprofile/profilephoto:…` 的非零、唯一用户标识建立摘要会话空间；不使用遥测 anid、MUID 或跨站 Bing Cookie。缺失、冲突或变化时停止任务。已用当前真实页面验证标识可读取且连续请求稳定，切号隔离另有模拟回归测试；尚未实测真实切号。

新版页面恢复手动授权入口及原有任务入口，未授权时显示网页积分和等级，授权后优先从原移动接口读取进度。**移动授权账号仍需用户自行确认与 Rewards 一致，脚本尚不能自动比对二者。** 新版不从磁盘恢复刷新 Token，也不自动执行任务；每次刷新需重新授权。旧 Web reportactivity 协议未适配，新页面缺少校验 Token 时不发送该通道；原移动接口是否接受请求及是否计分取决于微软响应，尚未完成真实授权和提交验收。不可将按钮可用视为任务已验证成功。

## 功能

- **悬浮面板**：显示会员等级、积分、搜索进度、签到状态、阅读进度、活动统计和运行日志。
- **每日签到**：尝试通过微软 Rewards 移动端接口提交签到，需要有效授权。
- **阅读与活动**：尝试提交可用的阅读任务和活动；并非所有活动都受支持。
- **搜索任务**：使用热搜或内置关键词执行搜索，包含随机间隔和阶段性暂停；这些措施不保证规避风控。
- **一键执行**：按“签到 → 阅读 → 活动 → 搜索”的顺序运行。
- **新增：打开仪表板后自动执行**：初始化结束后等待 5 秒，满足登录和授权条件时自动展开面板并启动一键执行。

## 安装

### 1. 安装脚本管理器

推荐使用 Chrome + Tampermonkey。只需要安装一个脚本管理器，不要让多个管理器同时运行同一个脚本。

| 管理器 | 官网 | GitHub |
| --- | --- | --- |
| Tampermonkey | https://www.tampermonkey.net/ | https://github.com/Tampermonkey/tampermonkey |
| ScriptCat（脚本猫） | https://scriptcat.org/ | https://github.com/scriptscat/scriptcat |

请从官网进入对应浏览器的官方扩展商店安装。下文以 Chrome + Tampermonkey 为例；不同管理器的权限支持可能有差异。

### 2. 允许 Tampermonkey 执行用户脚本（重要）

**仅启用扩展和脚本，不代表 Chrome 已允许执行用户脚本。** 如果 Tampermonkey 顶部出现“请启用‘允许用户脚本’扩展设置”的蓝色提示，需要完成以下配置：

1. 在 Chrome 地址栏打开 `chrome://extensions/`。
2. 找到 **Tampermonkey**，点击 **详细信息**。
3. 找到并开启 **允许用户脚本（Allow user scripts）**。
4. 检查扩展的 **网站访问权限**，确保允许访问 Bing、Rewards 及微软登录页面。
5. 返回 Rewards 页面并刷新。

不同 Chrome / Tampermonkey 版本的入口可能不同。如果找不到“允许用户脚本”，可尝试在扩展管理页面开启右上角的 **开发者模式**，并点击 Tampermonkey 蓝色提示中的帮助链接，按照当前版本的指引操作。

### 3. 安装本项目脚本

**方式 A：GitHub Raw 安装**

打开本仓库的 [`get-microsoft-rewards.user.js`](get-microsoft-rewards.user.js)，点击 **Raw**。如果脚本管理器弹出安装页面，确认安装即可。

**方式 B：手动复制安装**

1. 打开 `get-microsoft-rewards.user.js` 并复制全部内容，包括最上方的 `// ==UserScript==` 元信息。
2. 进入 Tampermonkey 控制面板，选择“添加新脚本”。
3. 删除默认代码，粘贴本项目代码。
4. 按 **⌘S（Mac）或 Ctrl+S（Windows）** 保存，确认脚本开关已启用。
5. 打开或刷新 <https://rewards.bing.com/dashboard>。

> 修改本地项目文件不会自动更新 Tampermonkey 中已安装的脚本。后续修改后，需要重新复制保存或重新安装。当前脚本的元信息仍保留上游链接，请勿将上游安装入口当成本仓库最新版本的入口。

## 首次运行与授权

1. 使用自己的微软账号登录 <https://rewards.bing.com/dashboard>。
2. 正常注入后，页面右下角会出现礼物图标，点击展开 Microsoft Rewards 面板。
3. 查看面板日志，等待积分和授权数据初始化。
4. 如果出现当前登录会话需要授权的提示，点击 **授权当前账号（自动接收）**，在新页面明确选择与 Rewards 网页一致的账号，完成登录/授权。
5. 微软跳转到回调页面后，脚本自动传回结果；返回 Rewards 页面确认所选账号一致，脚本自动兑换 Token，通常不需要复制 URL。
6. 授权成功后，可点击 **签到** 单独测试，或点击 **一键全部执行**。

### 自动接收授权（v1.0.18）

v1.0.18 修复首次没有授权码时 Token 请求锁可能保留已完成空 Promise 的问题，避免后续收到授权码仍直接返回空值。新增回归测试；兑换接口关闭自动重试（授权码为一次性），错误仅显示 HTTP 状态、白名单 OAuth 错误类型和说明，不输出原始响应或敏感字段。

v1.0.17 明确区分“网页会话标记”和微软账号：摘要不是邮箱或授权账号。一次性授权码不能直接显示账号，当前脚本没有可靠读取授权账号信息的实现，确认依靠用户在微软页面实际选择的账号。授权等待期间不再笼统提示“请确认已登录”。

v1.0.16 改用 Rewards 面板内的 **确认账号一致，完成授权 / 取消此次授权** 按钮，不再使用后台标签页可能被浏览器抑制的 `window.confirm`。授权结果收到后等待用户确认，5 分钟未确认会放弃。此前“已丢弃授权结果”不代表检测到了账号不一致，也可能是浏览器自动拒绝了后台确认弹窗。

v1.0.13 将注入时机改为 `document-start`，在微软回调页 DOM 加载之前立即接收授权结果，减少回调地址短暂停留后跳走导致的丢失。普通页面仍等待 DOM 就绪再显示面板。此方式无法保证捕获未加载文档的 HTTP 重定向，或被浏览器限制而未注入的回调。

- 需要允许 Rewards 页面打开弹窗，并允许本脚本在 `https://login.live.com/*` 运行。微软要求的登录、账号选择、同意授权或验证码仍需用户完成。
- 每次授权使用随机 `state`，绑定发起时的登录会话，10 分钟超时。超时、切号、拒绝授权或账号确认取消时，不兑换该次结果。
- 同一脚本存储内一次只开启一个授权流程；请保留原 Rewards 标签页。若流程被中断，可在 10 分钟后重试。
- 回调会短暂将授权码写入脚本管理器存储，由原页面消费并清除；脚本尝试清理回调页地址栏参数，但无法保证清理浏览器历史或网络记录。不要分享授权页地址。
- 页面结构、微软 OAuth 策略或脚本注入限制可能阻止自动接收。此时保留手动粘贴完整回调 URL 的备用方式。
- 当前仍不能自动核对微软授权账号与 Rewards 网页账号，必须确认二者一致。授权成功后不会立即自动启动任务，避免意外执行，请手动点击“一键全部执行”。

**不要向他人发送授权跳转 URL、授权码、Cookie、访问 Token 或刷新 Token，也不要将它们提交到 GitHub。** 脚本会通过脚本管理器存储刷新 Token，日志或截图分享前请检查是否含敏感信息。

## 配置：启动 Chrome 后自动运行

### 第一步：让 Chrome 启动时打开 Rewards

打开：

```text
chrome://settings/onStartup
```

选择 **打开特定网页或一组网页 → 添加新网页**，填入：

```text
https://rewards.bing.com/dashboard
```

这属于浏览器设置，脚本不会替你修改。它在启动 Chrome 时生效，不是每次新建标签页时生效。

**Mac 用户注意：** 关闭窗口不等于退出 Chrome。测试完整启动时，使用 **⌘Q** 退出 Chrome，再重新打开。

### 第二步：确认脚本自动执行配置

文件顶部 `CONFIG` 中已默认开启：

```js
autoRun: {
    enabled: true,
    delay: 5000
}
```

- `enabled: true`：开启自动执行；改成 `false` 即可关闭。
- `delay: 5000`：初始化结束后再等待 5000 毫秒（5 秒），不是从页面打开起固定 5 秒。

运行流程：

```text
启动 Chrome
  → 打开 Rewards dashboard
  → 初始化数据和授权状态
  → 等待 5 秒
  → 展开面板
  → 签到 → 阅读 → 活动 → 搜索
```

日志出现 **“🚀 一键执行开始”** 表示任务序列已经启动，不代表每项任务都成功。

### 自动执行的限制与防重复规则

- 仅在主机为 `rewards.bing.com`、路径以 `/dashboard` 开头时自动启动；其他 Bing 页面仍可手动执行。
- 缺少仪表板数据、缺少有效 Token 时，会跳过自动执行并提示先登录或授权；完成后请手动点击“一键全部执行”。
- 已有任务在运行或处于手动暂停状态时，不再次自动启动。
- 使用 `sessionStorage` 记录：**同一标签页当天自动启动一次后，刷新不再自动启动**。
- 标记表示“已启动”，并不表示“所有任务成功”；任务失败或中断后可以手动重试。
- 这是标签页级标记，不是整个浏览器的跨标签页锁。**不要同时打开多个 Rewards 标签页执行任务**。
- 浏览器恢复会话时可能恢复标记，因此重新启动 Chrome 不保证一定再次触发；必要时手动执行。
- 这是页面加载触发，不是每日定时任务。网页一直开着跨天，不会因此自动再次启动。
- 关闭或刷新执行中的页面会中断任务；浏览器后台节流、休眠或断网也可能影响任务。
- 一键执行会依次调用各模块，但不保证前一步失败就终止后续步骤。结果以微软服务端实际任务状态和积分为准。

## 同一浏览器切换微软账号（v1.0.15）

**v1.0.15 撤回跨站身份回退。** `cn.bing.com` / `www.bing.com` 的账号不能代表 Rewards 当前账号，不再要求登录 Bing 来通过 Rewards 身份检查。存储空间升级为 v3，不复用此前可能错配的授权和记录。只读到 Rewards Cookie、但无法解析页面账号时，不自动执行，也不从磁盘恢复刷新 Token；每次页面加载需要手动为 Rewards 当前账号授权。仍无法自动比对授权选择与 Rewards 网页身份，这是待解决的限制，不应视为完整的自动切号支持。

> 下述历史说明中的跨站 Cookie 回退策略已移除，以本节规则为准。

v1.0.11 在 Rewards 站点没有 `_U` 时继续检查 `www.bing.com/` 和 `cn.bing.com/`，选定来源后固定该来源检查，消失或变化时停止。诊断结果包含各站点 Cookie 名称和状态。**切号时必须确保 Bing 与 Rewards 登录的是同一个账号**：跨站点可能保留不同登录状态，Cookie 方案无法自动验证它们一致。不使用 MUID 等设备标识作为账号身份。如果所有站点均没有登录 Cookie，先打开 `https://www.bing.com/` 登录，再刷新 Rewards。

v1.0.10 修正了 Cookie API 请求地址没有尾斜杠的问题：`https://rewards.bing.com` 会被规范为 `https://rewards.bing.com/`，确保与 `@match https://rewards.bing.com/*` 的路径匹配。若此前出现 `the URL needs to be included by the scripts @include or @match tag`，请更新 Tampermonkey 中的脚本并刷新页面。身份诊断按钮同样已修正。

本版修复旧版授权、签到日期和搜索记录共用的问题：

- 优先读取 Rewards 服务端仪表板明确的账号字段（如 PUID/CID），无法识别时才使用登录 Cookie `_U`；对身份信息做 SHA-256 摘要，不在存储键中保存原始值。v1.0.8 同时兼容 `GM_cookie('list', ...)` 与 `GM_cookie.list(...)` 两种形式，不再只依赖 Cookie API。
- 刷新 Token、授权码、签到日期、搜索进度和自动启动标记均按登录会话隔离；旧版无归属的全局缓存不会复用。
- 每次业务请求前后检查登录会话，另每 15 秒及切回标签页时检查；发现身份变化或无法确认身份后，停止旧页面任务、尝试取消在途请求并清空旧显示，要求刷新。
- 面板显示会话摘要前 8 位，仅供区分登录会话，不是邮箱或稳定账号 ID。
- 停用静默获取授权码，避免微软登录页还保留另一个账号。新登录会话必须手动选择账号授权，并确认与 Rewards 网页账号一致。当前接口没有可靠的跨端账号比对，因此这个确认仍需要用户完成。

**切号步骤：**

1. 暂停当前任务，最好关闭其他正在执行的 Rewards / Bing 标签页。
2. 在微软网页退出旧账号并登录新账号。
3. 刷新 `https://rewards.bing.com/dashboard`；旧标签页提示身份变化时也需要刷新。
4. 在面板点击“授权当前账号（自动接收）”，**明确选择当前 Rewards 网页所用的新账号**，返回原页面确认，脚本会自动接收并保存授权；自动接收不可用时才手动粘贴回调 URL。
5. 确认账号一致后，手动点击“一键全部执行”。之后在该登录会话内可以使用自动执行。

登录 Cookie 可能在重新登录或会话轮换时改变，即使是同一账号也可能要求重新授权，这是保守的安全策略。若仪表板身份字段与 Cookie 都无法读取，脚本会显示具体的身份检查失败原因并停止，而不是复用旧账号授权；请先检查登录及扩展权限。旧版 Cookie 空间不会迁移到新版身份空间，首次更新可能需要重新授权。该机制不支持同一个 Chrome 个人资料中多个账号并行运行，也不能撤回切号前已经提交到微软的请求。

## 常见问题

### 没有礼物图标 / 没有浮窗

依次检查：

1. Tampermonkey 及 Rewards 脚本开关是否都已启用。
2. Tampermonkey 是否提示开启 **允许用户脚本**；按上文开启后刷新。
3. 扩展是否有当前网站访问权限。
4. 脚本是否完整安装，包括 `@match`、`@grant` 等元信息。
5. 当前网址是否匹配以下范围：

   ```text
   https://www.bing.com/*
   https://cn.bing.com/*
   https://rewards.bing.com/*
   https://login.live.com/*
   ```

6. 打开开发者工具的 Console，刷新页面，检查与用户脚本相关的错误。

页面自身的 CSP 提示、`unload` 权限提示或头像请求 404，不一定是脚本故障原因。优先解决 Tampermonkey 明确给出的权限提示。

### 有浮窗但没有自动执行

- 确认打开的是 <https://rewards.bing.com/dashboard>，而不只是 Bing 首页。
- 确认已安装本仓库含 `autoRun` 配置的新版代码，且 `enabled` 为 `true`。
- 等待初始化完成并查看日志，必要时先完成登录/授权。
- 当前标签页今天已自动启动过时，不会重复启动，点击“一键全部执行”即可。

### 签到失败 / 显示未签到 / 积分没有增加

- 查看面板日志，检查授权是否有效。
- 部分任务取决于地区、账号资格、日期和服务端配置，并非所有账号都提供。
- 脚本依赖微软页面结构和接口，接口变化可能导致失效；伪装移动端请求不保证能完成移动端专属奖励。
- 搜索过程中包含本地预估进度，日志中的提交成功或预估加分，不代表微软一定发放积分。
- 任务刷新时间依地区而异，跨天后可能需要等待。不要通过高频重试解决服务端限制。

### 清除旧账号授权和缓存（v1.0.14）

如果切号后仍显示旧账号数据，先关闭其他执行本脚本的标签页，然后在面板点击 **清除授权与缓存**，或通过 Tampermonkey 菜单选择 **清除所有本地授权与任务缓存（切号排查）**。

确认后会停止本页任务、清除本脚本所有账号的授权/签到/搜索记录及待处理授权，然后刷新。不删除微软 Cookie、账号或服务端积分。刷新后本标签页禁止自动启动，需要确认 Bing、Rewards、授权页为同一账号，重新授权后手动执行。新标签页仍遵循原自动执行配置。

这只是清理错配凭证，不是自动核对跨站账号的完整方案。`dashboardParsed: false` 时数据可能来自 Token 对应的账号，因此只看 Cookie 存在不能证明授权账号一致。

### 如何暂停或关闭自动执行？

- 执行过程中点击“一键全部执行”位置的暂停按钮；再次点击可继续。
- 将 `CONFIG.autoRun.enabled` 改为 `false` 并更新 Tampermonkey 中的代码，可关闭后续自动启动。
- 在脚本管理器中禁用本脚本，可停止后续页面加载时注入。

## 隐私与权限

脚本会读取相关微软站点的 Cookie、执行跨域请求、存储授权与进度，并访问第三方热搜服务获取关键词。第三方热搜域名包括：

- `hot.baiwumm.com`
- `hotapi.nntool.cc`
- `cnxiaobai.com`

安装前请审查 `@grant`、`@connect` 和请求逻辑，只使用信任的代码来源。不要把个人登录数据放入仓库。
